# Prototype Instructions

## État pédagogique - Terminale C, leçon 07

- La leçon « Coniques » vit dans `terminalCConicsPath.ts` : 11 niveaux, tous les exercices officiels 1 à 5 et exactement 10 000 XP. Les six identifiants historiques restent stables ; cinq niveaux ajoutent la piscine elliptique, les exercices de fixation, les deux renforcements et la mission complexe.
- Corrections sources à conserver : page 5, les directrices de `x²/4−y²=1` sont `x=±4√5/5` ; page 10, la translation de la parabole utilise le sommet `S`, pas `Ω` ; page 11, les foyers sont `(1;−2±√13)`, pas `√3` ; page 12, `A(5;0)` et `A′(−35;0)` donnent `AA′=40`, donc l’ellipse correcte est `(x+15)²/400+y²/144=1` ; page 14, la partie réelle contient `−y²`, et le cas `z=1` doit être traité avant de diviser par `z−1`.

## Durable project decisions

- The official structure logo is `src/assets/logo-excellence-officiel.png`, supplied by the user on 2026-07-19. Preserve its identity and do not replace it with a generated symbol.
- The selected visual direction is the first generated mock, “Cap Ivoire”: warm ivory surfaces, deep navy navigation, green/orange accents, generous spacing, and a single dominant lesson-resume action.
- Keep curriculum content and subject configuration separate from visual components so future subjects and programme updates do not require redesigning the shell.
- The student's level and series are chosen during registration and stored on the student profile. The dashboard must display them as fixed context, not as an editable selector. Subject choice is a separate control.
- Reserve a reusable profile-avatar slot next to the learner's greeting. The profile photo is optional during registration and may be added, replaced, or removed at any time from the Profile page. Center-crop and optimize the image in the browser before upload, accept only JPG/PNG/WebP, store it in the user's own protected `profile-photos` folder, show a preview before confirmation, and retain the neutral Phosphor user icon when `photoUrl` is absent.
- The first real Mathematics path is “Généralités sur les fonctions” for Seconde C, aligned with the DPFC programme (Thème 2). Keep paths data-driven, lessons sequentially unlocked, and lesson progress connected to the dashboard.
- Structure each interactive lesson around five reusable stages: understand, manipulate, method, exercise with explained correction, then success/unlocking. Keep printing and PDF export out of scope for now.
- Provide a dedicated administration center for authorized staff, covering platform monitoring, curriculum publishing, user access, operational queues, and global settings. Keep admin data and actions behind a replaceable storage layer so a secure backend can replace prototype persistence later.
- Keep level and series read-only everywhere in the learner experience, including the profile. Users must contact an administrator for an academic-year change; only an authorized administrator may update the stored combined level/series id. Resolve curricula and progress by that stored id, preserve progress per path, and show an explicit preparation state instead of leaking content from another class.
- Provide learner community spaces as first-class navigation destinations: scope rankings to the stored level and series, and keep messaging available independently from curriculum availability. Messaging is an authenticated private-conversation system backed by Supabase RPC/RLS with a SQLite fallback: students may contact classmates from the same stored level/series and authorized staff, parents may contact staff, and administrators may contact any profile. Preserve unread badges, replies, edit and soft-delete for the sender, read receipts, mute, archive/restore, search, automatic refresh, and real profile avatars.
- Authenticate through the dedicated `apps/api` service backed by Supabase Auth and PostgreSQL. Keep Supabase access tokens in frontend memory, rotate refresh sessions through `HttpOnly` cookies, persist profiles/progress behind RLS, and award XP only through the `submit_level_attempt` security-definer function. Use only a publishable key for normal API operations; never expose or require a secret/service-role key in the frontend. SQLite remains a replaceable offline fallback. Never expose the Admin destination to a student role.
- Keep local authentication reliable by starting `apps/api` automatically with the Vite development server when port 3333 is not already serving it. Authentication errors must display an actionable French message; never reduce a proxy or backend outage to the generic text “Une erreur est survenue”.
- Deploy Vercel as two coordinated projects: `excellence-lycee` serves the Vite SPA and proxies first-party `/api/*` traffic, while `excellence-lycee-api` serves the Fastify application through the catch-all Node function. Keep Supabase and server-only variables on the API project; preserve the first-party proxy so refresh cookies work without exposing tokens to the frontend.
- Use Davy as Excellence Lycée’s original virtual companion and guide. His canonical animation assets are `src/assets/davy-idle.webp`, `davy-blink.webp`, `davy-wave.webp`, and `davy-celebrate.webp`: a warm ivory and deep-navy guardian robot with an expressive human smile, articulated feet, gold star core, and green/orange details. Davy should give short contextual guidance, encouragement, and hints without obscuring content or giving answers directly; animate gently, react to guide opening and lesson completion, and respect reduced-motion preferences.
- Give Davy a narrated first-visit tour after sign-in. The learner must explicitly start audio, every spoken message must remain visible as text, and the tour must highlight the main destinations on desktop and mobile. Preserve mute, pause, replay, skip, per-account completion, and a Profile action to run the tour again; keep a text-only fallback when browser speech is unavailable.
- Davy's canonical voice is masculine, warm, and reassuring. Prefer a clearly identified French-speaking male system voice (including Ivorian or West African French when available) and use a deeper-pitch fallback when browsers do not expose voice gender.
- Use the founder-supplied, explicitly authorized recording as Davy's official cloned voice. Keep raw and optimized biometric voice samples plus the authorization outside published assets and source control; synthesize only through the authenticated API, cache repeated messages, and retain the masculine system voice as an automatic availability fallback.
- Start signed-out visits with a progressive Davy-led welcome: first choose Élève, Parent, or Enseignant; then choose connection or registration; only then show the relevant form. Persist the account audience separately from authorization roles, and ask adults which level/series they want to accompany.
- Let authorized administrators view real platform profiles and change any user’s combined level/series from the Users section. Validate the value server-side, keep the operation behind an admin-only database function, and write an audit log for every change.
- Structure Parcours as Subject → available lesson → sequential mastery levels. A level presents its learning content before the learner explicitly confirms understanding and starts one or more exercises. Grade attempts out of 20: 20/20 earns the level’s full XP, 10–19/20 earns half, and below 10 earns none. Passing unlocks the next level; the same exercises can be retried until the learner reaches the full XP award, while prior XP is never duplicated.
- Render mathematical notation with KaTeX instead of relying on Unicode combining glyphs. Curriculum prose may embed inline LaTeX between `$...$`; prominent formulas should use explicit `notationTex` or `formulaTex` fields while retaining plain-text fallbacks for accessibility.
- Use “Arène” as the learner training hub instead of a generic “Révisions” destination. Keep subject selection separate from six data-driven modes: Exercices, Devoirs, Duel, Exos type BAC, Compétition, and Quiz. The hub may present and select modes before their dedicated banks, matchmaking, timers, and event backends are connected.
- Structure the Arène exercise bank as level/series → subject → lesson → difficulty → stage. Every lesson has the three fixed difficulties Facile, Moyen, and Difficile, and each difficulty may contain any number of sequential stages with multiple exercises. Present learner stages as the same vertical mastery journey used in Parcours: central dotted line, alternating left/right cards, and diamond action nodes; keep these Arène exercise stages freely accessible until a dedicated completion rule is approved. Authorized `content_editor` users prepare Markdown/KaTeX statements and explained corrections in a simple split editor with instant learner preview, including explicit desktop and phone-sized preview modes. The editor preview must switch between the complete journey and the selected level content, include published sibling stages when calculating the next available stage, and render common pasted LaTeX commands even when contributors omit `$...$` delimiters. Contributors submit drafts for review and only administrators publish. Preserve the last published payload while a newer draft is edited so learner access is never interrupted.
- Filter learner-facing subject choices by the stored level/series. Philosophy must never be offered to a Seconde learner; keep this curriculum rule centralized in the subject configuration so it applies consistently to the dashboard, Parcours, and Arène.
